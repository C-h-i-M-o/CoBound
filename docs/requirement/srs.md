## 1. 引言

### 1.1 编写目的

本文档旨在对"协界（CoBound）——高校学生课程项目协作管理平台"进行完整的需求规格说明。文档面向以下读者：

- **任课教师**：评估项目需求分析的完整性与规范性
- **开发团队**：作为系统设计与实现的依据
- **测试团队**：作为验收测试的标准参考

### 1.2 项目背景

高校学生在小组作业、课程设计及竞赛项目中普遍面临以下痛点：

1. **组队困难**：缺乏基于课程和兴趣的高效组队渠道
2. **沟通混乱**：任务信息分散在微信、QQ 等多个工具中，关键信息难以追溯
3. **任务分配不明确**：缺乏可视化的任务归属与状态管理
4. **进度缺乏监督**：Deadline 临近才发现大量工作未完成
5. **贡献度不可见**：教师难以客观评估每个成员的参与程度

CoBound 旨在为一站式解决上述问题，提供从组队、任务分配到进度跟踪的全流程支持。

### 1.3 产品范围

CoBound 是一个基于 Web 的协作管理平台，核心能力包括：

- 项目创建与团队管理
- 任务看板（Kanban）、列表视图、路线图（甘特图）多视图管理
- 里程碑与目标（Goal）设定与跟踪
- 工时记录与日历排程
- 文档/wiki 知识库
- 多维度分析画布（SWOT、精益画布等）
- 角色权限控制（管理员/负责人/编辑者）
- 中文优先界面，链接式邀请加入

### 1.4 参考文献

- IEEE Std 830-1998: IEEE Recommended Practice for Software Requirements Specifications
- Leantime 3.8.0 开源项目（GNU AGPL v3）

## 2. 总体描述

### 2.1 产品视角

CoBound 是对开源项目管理系统 Leantime 3.8.0 的二次开发版本。系统保留上游的内部架构（PHP 命名空间、数据库结构、API 接口），对用户可见层进行品牌替换、中文本地化与新用户流程定制。

系统采用 B/S 架构，基于 PHP (Laravel 11) + MySQL 8.0+ 构建，前端使用 HTMX + jQuery + Bootstrap，支持 Docker 容器化部署。

### 2.2 用户角色

| 角色 | 标识 | 说明 |
|------|------|------|
| 管理员 (Admin) | admin | 系统级管理员，可创建/管理所有项目与用户 |
| 负责人 (Owner/Manager) | manager | 项目创建者或指定管理者，拥有项目内最高权限 |
| 编辑者 (Editor) | editor | 项目成员，可创建、编辑任务与内容 |
| 只读用户 (Reader) | reader | 仅可查看项目内容，不可编辑 |
| 教师 (Teacher) | 映射为 admin/manager | 可查看所管理项目的过程数据与成员贡献度 |
| 未激活用户 | — | 已通过邀请链接注册但尚未完成五步引导流程 |

### 2.3 运行环境

- **服务端**：PHP 8.2+, MySQL 8.0+ / MariaDB 10.6+
- **客户端**：现代浏览器（Chrome/Firefox/Edge/Safari 最新两个大版本）
- **部署方式**：Docker 容器化部署，支持 linux/amd64 平台
- **开发端口**：5080；**生产端口**：5180

### 2.4 假设与依赖

- 用户具备基本的计算机操作能力
- 服务器可连接互联网（用于获取容器镜像）
- 默认不依赖外部邮件服务（用户邀请使用链接方式）
- 数据存储依赖 MySQL，文件存储依赖本地文件系统

## 3. 功能需求

### 3.1 用户认证与账户管理

#### FR-AUTH-01 用户注册（邀请制）
- **优先级**: 高
- **描述**: 管理员创建新用户后，系统生成唯一邀请链接。受邀用户通过链接完成五步注册流程（账户设置 → 主题选择 → 个性化 → 作息设置 → 完成）。
- **输入**: 用户名、密码、头像（可选）、主题偏好、工作时间
- **输出**: 激活的用户账户，默认项目已创建

#### FR-AUTH-02 用户登录
- **优先级**: 高
- **描述**: 已激活用户通过用户名/密码登录系统。支持"记住我"选项。
- **输入**: 用户名、密码
- **输出**: 认证令牌，重定向至工作台

#### FR-AUTH-03 密码重置（联系管理员）
- **优先级**: 中
- **描述**: 用户忘记密码时，页面提示联系管理员。管理员在用户管理页面可重置任意用户密码。
- **输入**: 管理员操作：选择用户 → 设置新密码
- **输出**: 重置成功通知

#### FR-AUTH-04 个人资料管理
- **优先级**: 中
- **描述**: 用户可修改个人头像、姓名、密码、语言偏好、时区、主题（亮色/暗色）等。
- **输入**: 各项个人信息
- **输出**: 更新后的个人资料

### 3.2 项目管理

#### FR-PROJ-01 创建项目
- **优先级**: 高
- **描述**: 管理员/负责人可创建新项目，设置项目名称、详情、访问权限（公开/受限/仅指定成员）、预算（工时/金额）。
- **输入**: 项目名称、描述、权限设置
- **输出**: 新项目及其默认里程碑、任务、目标画布

#### FR-PROJ-02 项目列表与切换
- **优先级**: 高
- **描述**: 用户可在项目选择器中查看所有有权限的项目，并快速切换当前工作项目。
- **输入**: 选择目标项目
- **输出**: 切换后的项目工作台

#### FR-PROJ-03 项目仪表盘
- **优先级**: 高
- **描述**: 项目仪表盘展示项目进度、最新任务、团队状态更新（红/黄/绿）、检查清单、成员列表。
- **输入**: 进入项目
- **输出**: 可视化的项目概览

#### FR-PROJ-04 项目状态更新
- **优先级**: 中
- **描述**: 团队成员可使用红/黄/绿颜色快速发布项目状态更新，所有成员可见。
- **输入**: 选择颜色 + 文字说明
- **输出**: 项目时间线上的状态记录

#### FR-PROJ-05 项目检查清单
- **优先级**: 低
- **描述**: 系统根据项目完整性提供检查项（如已有里程碑、已有任务、已有目标等），帮助团队确认项目配置完整。

### 3.3 任务管理

#### FR-TASK-01 创建任务
- **优先级**: 高
- **描述**: 项目成员可创建任务，设置标题、描述、负责人、截止日期、优先级、标签、所属里程碑等。
- **输入**: 任务各项属性
- **输出**: 新任务卡片，出现在对应视图中

#### FR-TASK-02 看板视图
- **优先级**: 高
- **描述**: 以 Kanban 形式展示任务，列代表状态（新建/进行中/待审核/已完成等）。支持拖放改变状态、自定义列。
- **输入**: 拖放操作、列编辑
- **输出**: 更新后的看板状态

#### FR-TASK-03 列表视图
- **优先级**: 高
- **描述**: 以数据表格形式展示任务列表，支持排序、筛选、批量操作。
- **输入**: 筛选条件、排序字段
- **输出**: 符合条件的任务列表

#### FR-TASK-04 任务筛选与分组
- **优先级**: 中
- **描述**: 按优先级、状态、负责人、里程碑、日期等维度筛选任务。支持泳道（Swimlane）分组。
- **输入**: 筛选/分组条件
- **输出**: 过滤后的任务视图

#### FR-TASK-05 任务详情与评论
- **优先级**: 中
- **描述**: 点击任务可查看/编辑详情，包括描述、附件、子任务、评论和状态变更记录。
- **输入**: 任务编辑内容、评论
- **输出**: 更新后的任务信息

#### FR-TASK-06 工时记录
- **优先级**: 中
- **描述**: 在任务上可启动计时器或手动记录工时，关联到工时表。
- **输入**: 时间记录
- **输出**: 工时条目

### 3.4 里程碑管理

#### FR-MILE-01 创建里程碑
- **优先级**: 高
- **描述**: 创建项目阶段里程碑，设置名称、起止日期、标签颜色。
- **输入**: 里程碑名称、日期范围
- **输出**: 路线图上的新里程碑

#### FR-MILE-02 路线图视图（甘特图）
- **优先级**: 高
- **描述**: 以甘特图形式展示里程碑时间线，支持拖拽调整日期、缩放时间范围。
- **输入**: 拖放调整、时间范围选择
- **输出**: 更新后的里程碑时间线

### 3.5 目标管理

#### FR-GOAL-01 创建目标
- **优先级**: 中
- **描述**: 创建可量化的项目目标，设置目标描述、指标类型（百分比/数值/货币）、起始值、当前值、目标值，关联里程碑。
- **输入**: 目标属性与指标
- **输出**: 目标卡片及其进度条

#### FR-GOAL-02 目标进度跟踪
- **优先级**: 中
- **描述**: 更新目标指标值后，进度条自动反映完成程度。关联里程碑后，同时展示任务级执行进度。
- **输入**: 更新的指标值
- **输出**: 刷新后的目标进度

### 3.6 协作与沟通

#### FR-COLL-01 评论系统
- **优先级**: 中
- **描述**: 在任务、文件等内容上添加评论，支持 @提及成员。
- **输入**: 评论内容
- **输出**: 可见的评论与通知

#### FR-COLL-02 文件管理
- **优先级**: 中
- **描述**: 项目内上传、管理文件，支持文件夹组织。
- **输入**: 上传文件、创建文件夹
- **输出**: 文件列表

#### FR-COLL-03 通知系统
- **优先级**: 中
- **描述**: 当被分配任务、收到评论、任务状态变更时，系统发送站内通知。
- **输入**: 系统事件触发
- **输出**: 通知消息

### 3.7 知识管理

#### FR-KNOW-01 Wiki/文档
- **优先级**: 低
- **描述**: 项目内创建、编辑文档/Wiki 页面，支持多空间分类整理。
- **输入**: 文档内容、分类
- **输出**: 可浏览的文档

#### FR-KNOW-02 分析画布
- **优先级**: 低
- **描述**: 使用 SWOT 分析、精益画布、商业模式画布、同理心地图等工具进行项目策略分析。
- **输入**: 画布内容
- **输出**: 可视化画布

### 3.8 新用户引导

#### FR-ONBRD-01 五步注册引导
- **优先级**: 高
- **描述**: 新用户首次登录时，系统引导其完成：创建首个任务 → 命名项目 → 选择主题 → 设置作息 → 完成引导。每步都有中文说明。
- **输入**: 各步骤用户选择
- **输出**: 配置完成的个人工作环境

#### FR-ONBRD-02 工作台导览
- **优先级**: 中
- **描述**: 首次进入工作台、项目仪表盘、看板、里程碑、目标页面时，弹出 Shepherd.js 中文引导，介绍各区域功能。
- **输入**: 用户触发或首次访问
- **输出**: 导览步骤展示

### 3.9 迭代管理

#### FR-SPRT-01 迭代/Sprint 管理
- **优先级**: 中
- **描述**: 创建迭代周期，将任务分配到迭代中，查看迭代进度。
- **输入**: 迭代日期、任务归属
- **输出**: 迭代视图

### 3.10 用户管理（管理员）

#### FR-USER-01 用户创建与邀请
- **优先级**: 高
- **描述**: 管理员创建用户账户，系统生成唯一邀请链接。管理员复制链接发送给受邀者。
- **输入**: 用户名、角色、邮箱（可选）
- **输出**: 用户记录与邀请链接

#### FR-USER-02 角色与权限管理
- **优先级**: 高
- **描述**: 管理员可为用户分配系统角色（admin/manager/editor/reader），项目负责人可管理项目内成员角色。
- **输入**: 角色变更
- **输出**: 更新后的权限

## 4. 非功能需求

### 4.1 性能要求

| 指标 | 要求 |
|------|------|
| 页面加载时间 | 首屏 < 3s（不含首次冷启动） |
| 并发用户数 | 单服务器支持 50+ 并发操作 |
| 数据库响应 | 单表查询 < 100ms |

### 4.2 安全性要求

- 用户密码使用 bcrypt/Argon2 哈希存储
- 会话管理使用 Laravel Session 机制，支持 CSRF 保护
- API 认证支持 API Key 和 Sanctum Token 两种方式
- 邀请链接包含唯一随机令牌，防猜测
- 项目访问权限控制（公开/客户端内/仅指定成员三级）

### 4.3 可用性要求

- 默认语言为简体中文，界面全量中文化
- 主要功能页面提供新手引导（Tour）
- 支持亮色/暗色主题切换
- 支持桌面端与现代移动浏览器响应式布局
- 邀请流程不依赖外部邮件服务，降低部署门槛

### 4.4 可维护性要求

- 代码遵循 Laravel 标准架构（MVC + Service + Repository）
- 支持 Docker 一键部署
- 语言包独立于代码，通过 INI 文件管理，支持多语言扩展
- 插件系统支持功能扩展

### 4.5 兼容性要求

- 数据库兼容 MySQL 8.0+ / MariaDB 10.6+
- 浏览器兼容 Chrome/Firefox/Edge/Safari 最新两个大版本
- 部署兼容 Ubuntu 20.04 x86_64

## 5. 接口需求

### 5.1 用户接口

- 基于 Web 的图形用户界面
- 响应式设计，适配桌面与平板设备
- 主要交互模式：表单提交、拖放操作、看板卡片操作、甘特图时间轴操作

### 5.2 API 接口

- JSON-RPC 2.0 协议：`leantime.rpc.{domain}.{service}.{method}`
- REST 风格端点用于文件上传与下载
- i18n 词典 API：`GET /api/i18n`

### 5.3 数据库接口

- 数据表统一使用 `zp_` 前缀
- 核心数据表：`zp_user`, `zp_projects`, `zp_tickets`, `zp_canvas`, `zp_canvas_items`, `zp_timesheets`, `zp_files`, `zp_comments`

---

## 6. 约束条件

- 基于 Leantime 3.8.0 二次开发，不修改内部命名空间（`Leantime\...`）和数据库结构
- 遵守 GNU AGPL v3 开源许可协议
- 生产环境目标平台为 Ubuntu 20.04 x86_64
- 中文翻译覆盖所有用户可见内容，技术标识（URL、iCal 等）保留原文
