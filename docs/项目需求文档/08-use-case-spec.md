# 用例规约

## UC-01 学生申请加入团队
- 参与者：学生
- 前置条件：学生已登录并选择课程。
- 主流程：学生浏览团队列表，查看团队需求，提交申请理由；团队负责人查看申请并同意或拒绝；系统通知申请结果。
- 异常流程：团队人数已满时禁止提交；重复申请时提示等待处理。
- 验收标准：申请状态可追踪，申请结果会生成通知。

## UC-02 分配任务
- 参与者：学生负责人
- 前置条件：项目已创建，团队成员已加入。
- 主流程：负责人创建任务，填写标题、描述、负责人、截止时间和优先级；系统通知责任成员；成员确认通知。
- 异常流程：截止时间早于当前时间时禁止保存；未指定负责人时提示补全。
- 验收标准：任务出现在项目任务列表和责任成员个人待办中。

## UC-03 更新进度
- 参与者：学生
- 前置条件：学生存在待办任务。
- 主流程：学生进入任务详情，更新完成百分比、状态和说明；系统记录更新时间。
- 异常流程：已归档项目不可修改进度。
- 验收标准：团队看板和教师端进度总览同步更新。

## UC-04 查看风险预警
- 参与者：学生、教师
- 前置条件：项目存在任务或通知数据。
- 主流程：系统根据逾期任务、临近Deadline、未确认通知和低进度生成风险；用户查看风险原因。
- 异常流程：无风险时展示正常状态。
- 验收标准：风险必须包含触发原因和关联任务或通知。

## UC-05 查看并调整贡献度
- 参与者：教师
- 前置条件：项目已有过程数据。
- 主流程：教师查看成员任务完成率、延期次数、通知响应和阶段提交记录；系统生成参考分；教师可填写调整分和说明。
- 异常流程：过程数据不足时显示“参考不足”，不强制生成高置信分。
- 验收标准：调整记录保留教师、时间和理由。
