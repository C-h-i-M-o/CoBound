# 可行性分析报告

## 技术可行性
项目首版规划使用 Next.js 全栈、TypeScript、SQLite + Prisma。该方案适合快速开发响应式Web端，能够在单一代码库中完成页面、API和数据访问。SQLite适合课程演示和本地部署，后续可迁移到PostgreSQL。

## 经济可行性
项目可使用开源技术栈完成，开发、测试和部署成本较低。首版不接入收费短信、邮件或微信服务，只在系统内实现通知与确认能力，因此成本可控。

## 操作可行性
高校学生和教师普遍熟悉Web系统和移动浏览器。系统以课程、团队、任务和提醒为核心概念，学习成本较低。管理员只需维护基础数据和系统配置，不承担复杂业务操作。

## 时间可行性
首轮先完成需求文档和静态线框图，降低后续开发返工。MVP开发可按学生端、教师端、管理员端逐步推进，适合课程项目周期。

## 风险与对策
| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 学生不愿重复维护任务 | 进度数据不完整 | 简化任务上报入口，突出Deadline和提醒价值 |
| 贡献度评分争议 | 教师采纳度下降 | 系统只提供参考分，教师可调整并查看依据 |
| 微信小程序后续接入 | API重构成本 | 首版API避免强绑定Web页面状态 |
| 实时沟通需求膨胀 | 项目范围失控 | 首版只做通知确认，不做聊天 |
